## Units and anchors

Source pixels are the baked grids at ART_DENSITY=2; logical dimensions divide those by two. The world/screen columns explicitly use the ordinary 2× actor scale and 2× map zoom, not boss scale 3 or Marmalade scale 1.5. All ordinary world actors/props are bottom-center anchored; terrain is tile-aligned. Town buildings use their existing multi-tile footprint fitter. The v3 scene ledger reports actual companion scale separately. Required custom frames are not implemented merely because a role is inventoried.

## Key gaps / decisions

- **Hero size**: the current proposal uses the user-reference knight (64px cells, visible height ≤48px, 2× screen scale). The older knight_m candidate is 16x28 in pack; current hero is 16×22 logical / 32×44 baked source / 32×44 world / 64×88 screen. Native source-to-world 2× gives 32×56 world and 64×112 screen, taller than current. First preview must show this before bounds approval.
- **Missing directions**: pack humanoids are mostly front-facing/side-run sets; current runtime expects front/back/left/right for knight, goblin, skeleton, orc, mage, healer, merchant, prisoner, princess, villager. The reference-derived player now has four proposed directions/walking poses in preview; matching back/side work remains for the other humanoids.
- **No direct pack match**: bat, wasp, hydra, boar, medusa, skeletonKing, dragonBoss, cook, bartender, cat/catCompanion/dog/chicken, most town buildings/landscape, key/scrolls/spellbooks, many hazards/FX, armor/helmet/shield/ring, throne, flame vents, rubble/tombstone/crystal/cookingPot/barCounter/doorstep/water/bridge.
- **Direct/close pack matches**: goblin, skelet, orc_warrior, wizzard families, chest/flasks, floor_spikes, stairs/ladder, columns, banners, doors, weapons/bows/arrow, floor/wall atlases.
- **Pip/planned companion**: if implemented by integration time, Pip needs a custom dog-companion mapping in the manifest; not a new gameplay feature in this art pass.
