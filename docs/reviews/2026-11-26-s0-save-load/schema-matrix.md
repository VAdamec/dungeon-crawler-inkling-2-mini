This is a persistence contract for later requested phases, not a production schema/helper. [Review](README.md) · [observed record keys/types and probes](probes.json).

## Nested semantic records

Observed keys/types are retained in probes.json; optional undefined source fields disappear from JSON and must have explicit absent/default semantics. Unknown keys are rejected rather than merged. Static definitions may use canonical IDs in the final DTO; do not trust imported arbitrary names, art roles, modifiers or functions.

All actor positions are logical world coordinates. Do not validate unique coordinates across different entity categories: hero/key/loot/stairs can overlap intentionally, ordinary monsters can walk over hazards/NPC tiles/companions, and corpses can share a live actor's tile. Companion placement can temporarily cease being adjacent/open as monsters move; load must not call placement helpers to “repair” a saved actor. Validate in-bounds/walkable actor tiles, scoped IDs and real cross-field rules instead.

## Canonical references and active overlays

| Context | Source relationship / stale case | Snapshot and hydrate rule |
| --- | --- | --- |
| Active dungeon | Arrays/objects usually alias `floors[depth][field]`. Filtering potions/treasures replaces the active array; scalar hazardTime changes without a cache update. Probe: current potions=3 vs cached=4; time=3.75 vs 0. | Purely copy cached floor metadata, overlay **every current FLOOR_FIELDS value**, then separately store current encounter. Keep wrapper descentRewarded. On load make active fields point to the canonical decoded floor objects; scalar changes still follow existing saveFloor behavior. |
| Active town | state map/visited/props alias town; state.merchant = town.store = town.landmarks.store. Store stock can be replaced. | Overlay current map/visited/props/merchant without calling saveTown; reconstruct all three store references as one object. |
| Town in either area | inn/townGate reference landmarks. `town.landmarks.companionBoard` is the same object included in town.props. | Decode a single board prop and link the landmark; link inn/gate from town. Do not duplicate store/board in ways that lose identity. |
| Current boss | `state.boss` belongs to state.monsters, including a just-defeated corpse; floor templates are independent copies. | Link by scoped bossId; never link the live boss to monsterSpawns or recreate it. |
| Current guards | Summons append only to state.monsters, not monsterSpawns; saveFloor does not add them. | Include in current encounter. On later travel existing recreation drops these rows; do not add guards to templates. |
| New run vs same run | Companions/unlocks/cat/return/timing excluded from FLOOR_FIELDS but meaningful in external saves. | Persist same-run progress explicitly; leave R/newGame reset rules intact. |

`saveFloor`, `saveTown`, `render`, `revealAroundPlayer`, `equipItem`, `activateCompanion`, travel and generation are unsuitable pure-export/validation shortcuts: they write caches/state/UI or emit effects. Snapshot uses explicit copies; S2 derives camera and paints after its atomic candidate commit without increasing exploration or replaying milestones.

## S0-selected implementation policies

These are engineering recommendations reconciled in S0, not additional user approvals or implementation authorization.

- Save from a started living visible town/dungeon at a logical boundary. Own Help/Save UI is allowed; inspect its underlying pause/context. Reject console, trade/picker state **or stale visible overlays**, health/retreat prompts, unfinished boss/ending cinematics and gameOver. v1 rejects saving with godMode on; godMode off is required on restore. Cheat-granted gold/scrolls remain ordinary data; this is not anti-cheat and godMode off does not prove an unmodified run.
- Load from launch, stable living play or ordinary death; Help/own Load UI may host it. Reject hidden/modal/cinematic/ending contexts. Reading/preview freezes all relevant simulation clocks; invalidate on R/travel/death/cancel/newer session, and recheck identity/context before commit. Save eligibility and load eligibility are separate predicates, neither a blind simulationBlocked call.
- Keep 32 MiB UTF-8 input/output byte cap, with bounded per-field/count/depth rules in the review. Over-limit export reports a clear refusal **without truncating progress**. Import checks File.size before reading, and text byte budget for direct parser entry. Text limits/structural limits are v1 format constraints, not new gameplay caps.
- Do not treat all numbers as safe integer counts: XP/thresholds follow existing finite-number progression. Counts/IDs/currency use safe-integer validation; subsecond clocks and potion fractions are finite fractional numbers. Do not enforce a derived level→maxHP equation or repair current market HP/spell leaks during persistence.
- Exact current encounter includes corpse rows to preserve subsequent guard ID allocation. No history pruning/compaction or new summon behavior in S1/S2. The source has no absolute lifetime maximum; never claim two generated fixtures prove one. A future compact-history format is separate work.
